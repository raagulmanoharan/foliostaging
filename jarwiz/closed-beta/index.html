Put the project in view.

Drop in a PDF, paste a link, or add a note as an idea comes to you. Move related items together. Keep the floor plan beside the program, and the details you need are there when you start writing.

Ask a question across your sources.

Select the material you want Jarwiz to use. Ask it to compare options, pull out a theme, or suggest a next step. Read the answer beside the sources and decide what belongs in your project.

Make the thing your project needs.

Choose a format that fits the question. Write a brief from an interview, map a process someone can follow, or try an interface before handing it to a developer. You can keep working on the result right on the board.

Give the first draft another pass.

Add a new constraint, ask a follow-up question, or change a detail yourself. The earlier material stays on the canvas, so you can revise the draft in the context of the project.

In development

Shared workspaces

We’re building toward shared boards where teammates can discuss a draft and bring updates from connected tools into the same workspace.

Open source, with room to build.

Jarwiz’s own code is MIT-licensed. Read the source, follow the local setup guide, or build on the canvas for your own projects. Third-party components have their own licenses.

Jarwiz uses Claude today. We’re developing an open harness, a shared interface that lets different AI models work with the board and its tools. The goal is to change models while keeping your project in place.
